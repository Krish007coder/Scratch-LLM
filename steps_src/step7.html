Ollama Integration & Text Chunking

Line-by-line inspection of ollama_client.py and text chunking strategy

1. Under the Hood: Text Chunking Strategy

To perform vector searches on text documents, we must divide them into smaller segments (chunks) before generating embeddings. Large files can exceed the model's context window (e.g. 8192 tokens for nomic-embed-text). Additionally, embedding small, semantically coherent segments (e.g. 200–300 words) yields more precise search results than embedding entire documents.

2. Sliding Window Math

To avoid losing context at chunk boundaries, we use a Sliding Window approach with a coordinate offset overlap. Let chunk_words be the chunk size and overlap_words be the overlap size. The sliding step is calculated as:

step = chunk_words - overlap_words

Using a step of 220 words with a chunk size of 250 words creates a 30-word overlap. This overlap ensures that sentences or concepts that cross a boundary are captured in both adjacent chunks, maintaining context across segments.

vectordb/ollama_client.py
Local Ollama Client Implementation
pythonimport requests
from typing import List

class OllamaClient:
    embed_model = "nomic-embed-text"
    gen_model = "llama3.2"

    def __init__(self, host: str = "127.0.0.1", port: int = 11434) -> None:
        self._base = f"http://{{host}}:{{port}}"

    def is_available(self) -> bool:
        try:
            r = requests.get(f"{{self._base}}/api/tags", timeout=2)
            return r.status_code == 200
        except requests.RequestException:
            return False

    def embed(self, text: str) -> List[float]:
        try:
            r = requests.post(
                f"{{self._base}}/api/embeddings",
                json={{"model": self.embed_model, "prompt": text}},
                timeout=33
            )
            r.raise_for_status()
            return r.json().get("embedding", [])
        except requests.RequestException:
            return []

    def generate(self, prompt: str) -> str:
        try:
            r = requests.post(
                f"{{self._base}}/api/generate",
                json={{
                    "model": self.gen_model,
                    "prompt": prompt,
                    "stream": False,
                    "options": {{"temperature": 0.2}}
                }},
                timeout=60
            )
            r.raise_for_status()
            return r.json().get("response", "")
        except requests.RequestException as e:
            return f"Error generating answer: {{str(e)}}"
Code Analysis:
  • timeout=33: Connect timeouts are kept low, while read timeouts are generous. This allows the local server to load and process the model on its first run without raising client exceptions.
  • "stream": False: Disables streaming responses, returning the completed output in a single HTTP response to simplify parsing.
  • "temperature": 0.2: Configures the model to generate more focused, deterministic responses, which is ideal for fact-based retrieval tasks.
