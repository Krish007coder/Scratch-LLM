Version Control & Deployment

Deploying to the cloud and publishing via Git

1. Production Deployment Architecture

For production deployments, running Flask's built-in development server is not recommended. It is not designed to handle high concurrency, SSL/TLS encryption, or resource management. Instead, we use a production-ready WSGI server like Gunicorn behind a reverse proxy like Nginx or Traefik.

Production Web Architecture Flow
[ Client Browser ] ---> ( HTTPS / Port 443 ) ---> [ Nginx Reverse Proxy ]
                                                        |
                                                        v ( Gunicorn socket / Port 8080 )
                                                 [ Flask Application ]
                                                        |
                                                        v ( REST / Port 11434 )
                                                 [ Ollama Service ]

2. Containerization with Docker

To run our VectorDB service reliably across different environments (local development, staging, or cloud production), we containerize the application using Docker. This packages our Python dependencies, Flask server, and database wrapper into an isolated file system image.

Dockerfile
Production Container Build Configuration
dockerfile# Use a lightweight python image
FROM python:3.9-slim

# Set environment variables
ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1
WORKDIR /app

# Install system dependencies
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    && rm -rf /var/lib/apt/lists/*

# Install python dependencies
COPY requirements.txt /app/
RUN pip install --no-cache-dir -r requirements.txt
RUN pip install --no-cache-dir gunicorn

# Copy application files
COPY . /app/

# Expose server port
EXPOSE 8080

# Start server using Gunicorn with 4 worker threads
CMD ["gunicorn", "--bind", "0.0.0.0:8080", "--workers", "4", "--threads", "2", "main:app"]

3. Orchestrating with Docker Compose

To manage both our VectorDB Flask server and local Ollama service together, we can orchestrate them using Docker Compose:

docker-compose.yml
Multi-Service Orchestration
yamlversion: '3.8'

services:
  vectordb:
    build: .
    ports:
      - "8080:8080"
    depends_on:
      - ollama
    environment:
      - OLLAMA_HOST=ollama
      - OLLAMA_PORT=11434

  ollama:
    image: ollama/ollama:latest
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama

volumes:
  ollama_data:
