2. Database Separation Rationale

To showcase search algorithms and evaluate latency under identical conditions, this project separates data into two independent modules:

  1. VectorDB (16D Demo): Operates on a hand-crafted 16-dimensional vector set. It executes queries on three search structures (Brute Force, KD-Tree, HNSW) simultaneously to visualize and compare their performance.
  2. DocumentDB (768D Production Mode): Manages real text documents. It converts pasted texts into 768-dimensional embeddings using Ollama, which are then stored in a dedicated HNSW index for the RAG pipeline.

3. The RAG Pipeline Data Flow

Retrieval-Augmented Generation (RAG) Flow
[ User Question ] ---> ( Ollama Embedding ) ---> [ 768D Query Vector ]
                                                          |
                                                          v
[ Response Answer ] <--- ( Generate Model ) <--- [ Context Prompt ] <--- [ HNSW Index ]
  • Ingestion Pathway: Text input is chunked into 250-word segments with 30-word overlap. Each chunk is sent to Ollama's /api/embeddings endpoint, generating a 768-dimensional float array stored inside HNSW.
  • Search Pathway: The user's query is embedded into a 768-dimensional vector, which is searched against the HNSW index. Chunks with Cosine distance ≤ 0.7 are retrieved.
  • Generation Pathway: The text of the retrieved chunks is concatenated to form a system prompt context. Ollama runs the context and question through llama3.2 to generate the final answer.

4. Production & System Design Trade-Offs

Monolithic App vs Microservices:

  • Monolithic (Our Setup): In-memory indexes run in the same OS process as the Flask web server. This has low complexity and near-zero inter-process communication overhead. However, it cannot scale compute independently of storage.
  • Microservices: Decoupling distance computations into dedicated compute nodes (e.g., using Triton Inference Server) and storage/indexing into search nodes. This allows horizontal scaling but increases network latency.
