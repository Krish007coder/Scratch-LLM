Introduction & Overview

What we are building, why we are building it, and our design decisions

Welcome! This CodeLab is a comprehensive guide to understanding and building a production-inspired Vector Database from scratch. Rather than utilizing pre-packaged library blocks like FAISS, Pinecone, or scikit-learn, we build the core math, algorithms, and interfaces in raw Python.

By coding this end-to-end, you will gain an intuitive, interview-grade understanding of how spatial structures function in high dimensions, how graphs can navigate datasets rapidly, and how local LLM workflows combine with searching indexes to form Retrieval-Augmented Generation (RAG) systems.

Why Do Vector Databases Exist?

Traditional SQL and NoSQL databases index documents using keys, indices, or keyword indexes (like B-Trees and Inverted Indexes). However, queries like "similar sound signatures" or "semantically equivalent concepts" cannot be resolved via direct string matching. We convert these inputs into arrays of numbers called embeddings. These capture the semantic essence of the data in high-dimensional vector space. A vector database is designed specifically to index and search these arrays with extreme efficiency.

Under the Hood: Hardware & Memory Constraints

In-memory dense vectors are stored as contiguous arrays of floating-point numbers. For a dataset of N vectors in d dimensions, a brute-force scan requires loading N * d * 4 bytes of memory (for float32 precision) into CPU cache lines. At scale (e.g., N = 10^7, d = 768), a single query forces the traversal of approximately 30.72 GB of raw data. Contiguous allocations allow sequential prefetching, whereas pointer-chased heap objects (such as Python lists of floats) cause random memory references and L1/L2 cache misses.

The Curse of Dimensionality

As the dimension d increases, the volume of space grows exponentially relative to the distance, and data points become nearly equidistant. Traditional spatial partitioning structures like KD-Trees fail to prune nodes, degrading search times to linear scans.
